数据来源与口径说明

实时层。站点通过本地 Node 代理请求 Liquipedia：赛事日期取自 S-Tier Tournaments/Post 2023 页面中的赛事时间轴； 逐场比赛则按赛事抓取对应页面的子阶段页（如 /Playoffs、/Stage 3）， 解析其中的对阵、时间与逐图比分。全程不需要任何 API Key。

兜底层。若代理不可用（例如直接以 file:// 打开，或访问 GitHub Pages 上的托管版）， 站点自动回落到内置的 data/tournaments.json 快照。赛历功能完整，只是不再自动更新、也没有逐场数据。

托管版的差异。GitHub Pages 只能托管静态文件，无法运行 Node 代理，因此托管版用的是构建时烘焙进仓库的赛程快照； 流水线每天会尝试刷新两次（Liquipedia 对数据中心 IP 较严格，刷新失败时会保留原数据）。 想要实时数据，把仓库克隆到本地执行 node server.js。

为什么需要本地服务。Liquipedia 的 api.php 不返回 Access-Control-Allow-Origin，浏览器直连会被 CORS 拦截；其接口条款同时要求 使用可识别的 User-Agent，而浏览器不允许自定义该请求头。代理内置缓存并把请求间隔控制在 2 秒以上，以遵守对方的接口频率要求。

逐场数据的限制。为避免给对方接口造成压力，时间范围超过 21 天时不会拉取逐场数据； 另外，并非所有赛事都在 Liquipedia 上有独立的比赛页，没有对应页面的赛事会显示为「无逐场数据」。

日期为什么可能看到两个版本。主办方官网通常给出「含线上阶段 + 场馆阶段」的完整赛期， 而赛事日历一般只记正赛/场馆阶段。本看板主日期采用后者，主办方口径会作为附加标签显示在卡片内。
